# Proposal

## Why

当前页面以功能平铺为主：对局输入区域位于上一轮联想线索之前，结果页的详细时间与排行榜争夺注意力，同词和成功主要依靠静态文字表达。需要以移动端窄屏为优先，建立清晰的信息层级，并通过关键时刻的短暂庆祝，让玩家获得明快轻派对的共同游玩体验。

## What Changes

- 统一首页、邀请入房、准备房间、对局和结果页面的视觉节奏，突出每个阶段的主要信息与操作；沿用全部 daisyUI 主题及其语义色。
- 以 320px、360px、390px 窄屏为首要验收尺寸，处理长词、长昵称、多人列表、触控、软键盘和安全区域；宽屏在此基础上扩展布局。
- 对局按轮次与倒计时、上一轮线索、作答、玩家状态排列；详细规则、历史和完整统计通过明确入口按需展开。
- 增加准备状态、开局倒数、提交确认、答案揭晓和下一轮切换的短暂反馈。
- 新揭晓轮次中，至少两位有效玩家同词时，对对应组显示同步轻弹、高亮、人数与实际加分；多个同词组独立呈现。
- 成功时突出共同词并播放一次短暂彩带；失败保留柔和反馈和清楚的结束原因。庆祝不阻塞任何操作。
- 将实时庆祝与静态答案展示分开，避免历史回看、下一轮参考、刷新、重连及重复快照重播；支持减少动态效果偏好和有限的动画资源预算。

## Capabilities

### New Capabilities

- `game-presentation`：拥有各游戏阶段的信息层级、窄屏交互、主题一致性和由已公开状态驱动的一次性动效行为。

### Modified Capabilities

无。现有房间、轮次、结果和会话规则保持原有契约；新增表现要求集中在 `game-presentation`。

## Impact

- 主要涉及 `src/client/App.tsx`、`game-screen.tsx`、`use-room.ts`、`history.tsx`、`lobby-settings.tsx`、`theme-switcher.tsx`、`invite-status.tsx`、`style.css`，按职责提取页面和动效组件。
- 复用 `Snapshot`、`RoundView.groups`、`AnswerView.points` 与 `Result`；无需更改服务端、共享协议、计分、词语隐私和阶段时长。
- 普通反馈使用 CSS；拟新增 `canvas-confetti` 处理成功彩带，不引入第二套 UI 库或通用动画框架。
- 实施时同步 README 的外观与浏览器验收说明；验证以窄屏真实流程和动效触发边界为主，仅为容易漏检的触发逻辑增加最小测试。
- 本次不包含音效、震动、账号、持久化、游戏规则调整或额外的动效设置系统。
