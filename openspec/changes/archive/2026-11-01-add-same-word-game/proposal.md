# Proposal

## Why

将依赖线下同步出词的同词游戏做成可通过浏览器访问的多人房间，让 2～99 位玩家可以独立作答、同时揭晓，并在有限轮次内寻找共同词。统一计时、弃权、历史词校验和计分规则，使短暂断线与多人同时操作不会影响判定的一致性。

## What Changes

- 新增创建房间、通过房间码或邀请链接加入、设置展示 ID、房主配置和全员准备流程；人数上限 2～99、最多轮数可设为 2～999、每轮作答时限可设为 1～600 秒。
- 新增页面主题按钮，支持全部 daisyUI 内置主题；默认按系统偏好使用 light／dark，支持记住手动选择与恢复跟随系统。
- 首次随机出词计为第 1 轮并纳入最多轮数；后续参考上一轮全部词语联想、隐藏作答、统一揭晓和逐轮推进。作答时限是最长等待时间，全员提前完成即结算。
- 同词判断去除首尾空白并忽略大小写；禁止使用本局之前轮次中任何玩家已成功提交并被揭晓的词。重复历史词提交失败，可在原截止时间内重新作答；同一轮内允许不同玩家提交同词。
- 新增部分同词每人加 1 分、全员同词每人加 100 分、成功／失败统计和确认回到准备页面的流程。
- 主动退出或到期未作答只淘汰本人；有效玩家不足 2 人时失败。刷新及短暂断线可恢复原身份，倒计时不暂停。
- 房间、会话、对局和积分全部保存在单个服务进程的内存；重启后清空，不恢复房间或进行中的对局。
- 本期范围不包含账户注册、跨局排行榜、数据库、观战、中途补位、聊天、AI 判词或多实例部署。

## Capabilities

### New Capabilities

- `room-lobby`：房间创建与加入、人数与配置校验、展示身份、房主转交、准备与开局。
- `round-gameplay`：多人轮次、私密提交、大小写不敏感的同词键、历史词禁用、计时、弃权及揭晓。
- `game-results`：分组计分、胜负优先级、统计与轮次历史、庆祝或失败页面以及再开一局。
- `session-recovery`：匿名身份、实时同步、重连、重复命令处理、权限与内存生命周期。

### Modified Capabilities

无。当前项目没有既有能力规格或业务实现。

## Impact

- 这是新项目：新增浏览器端、Node.js 服务端及共享协议与校验模块，采用单个包管理项目并按目录分离职责。
- 建议采用 TypeScript、React、Vite、Tailwind CSS 与 daisyUI；服务端使用 Fastify、Socket.IO，客户端命令使用 Zod 校验。
- 新增同源 HTTP 会话／静态资源／历史查询接口及 Socket.IO 房间命令、状态快照与结算通知；服务器负责身份、截止时间、积分与胜负的最终裁决。
- 部署为一个支持持久连接的 Node.js 服务，通过 HTTPS 提供页面及实时连接；无数据库、Redis 或外部游戏服务依赖。
- 交付可运行的单服务游戏，并聚焦验证计分、历史词、截止时间、弃权、消息重复、答案保密及身份恢复边界。
